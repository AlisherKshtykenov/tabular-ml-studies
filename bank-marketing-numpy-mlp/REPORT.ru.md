# Подробный отчёт: логистическая регрессия, MLP и своя нейросеть

**Вывод.** Все модели намного лучше наивной: PR-AUC 0.42–0.45 против 0.117. Своя сеть на numpy с двумя скрытыми слоями работает наравне с библиотечными и на случайном разбиении статистически лучше логистической регрессии, но прибавка небольшая: 60.8% согласий против 57.1% при звонках 20% клиентов. При проверке по времени ROC-AUC всех моделей падает с 0.77–0.79 до 0.63–0.65, поэтому числа случайного разбиения нельзя считать прогнозом на будущее.

Код и графики: [notebooks/bank_marketing_mlp.ipynb](notebooks/bank_marketing_mlp.ipynb). Таблицы: `results/tables/`. Графики: `results/figures/`. Расчёты: scikit-learn 1.9.1, numpy 2.5.4, torch 2.14.1, `random_state=42`.

## 1. Задача и данные

**Задача.** До звонка оценить, откроет ли клиент срочный депозит (1 = откроет). Бинарная классификация с дисбалансом. Банк сортирует клиентов по оценке модели и сначала звонит тем, у кого шанс выше.

**Метрика.** Главная PR-AUC: она оценивает сортировку и учитывает редкость согласий. Accuracy не подходит: модель «всем отказ» даёт 88.3%.

**Данные.** [Bank Marketing, UCI](https://archive.ics.uci.edu/dataset/222/bank+marketing), DOI 10.24432/C5K306, лицензия CC BY 4.0. 45 211 строк, 16 признаков, согласий 11.7%. Подробности: [data/info/dataset.md](data/info/dataset.md).

## 2. Предобработка и feature engineering

| Решение | Почему |
|---|---|
| Удалён `duration` | Длительность известна только после звонка, это утечка |
| `unknown` оставлен отдельной категорией | Отсутствие сведений несёт сигнал |
| `pdays = -1` → `was_contacted_before`, `recency` | −1 означает «не звонили», как число бессмысленно |
| `balance`, `campaign`, `previous` → логарифм | Сжатие хвостов (асимметрия до 41.85), выбросы не удаляются |
| `is_young_or_senior` | Доля согласий по возрасту U-образная |
| `has_any_loan`, `is_negative_balance` | Флаги кредитной нагрузки |
| StandardScaler, OneHotEncoder | Обучаются только на train |

|---|---:|---:|---:|

| val | 6 782 | 794 | 0.117 |

После обработки 54 столбца: 10 числовых и 44 one-hot.

Новые признаки помогают линейной модели, у сети прирост в пределах разброса: часть зависимостей она строит сама.

## 3. Визуализация и анализ распределений

Графики 01–05 в `results/figures/`.

- **Дисбаланс:** 88.3% отказов и 11.7% согласий.
- **Сдвиг во времени:** доля согласий растёт с 3.0% в начале файла до 47.1% в последней десятой части.
- **Хвосты:** асимметрия `previous` 41.85, `balance` 8.36, `campaign` 4.9.
- **Самые сильные категории:** `poutcome = success` 64.7%, студенты 28.7%, пенсионеры 22.8%, `contact = unknown` только 4.1%.
- **Возраст:** 24.0% до 25 лет, 9.1% в 40–50 лет, 40.5% в 60–70 лет.
- **Месяц частично заменяет период.** Сентябрь, октябрь и декабрь почти целиком лежат в конце файла. В одних и тех же месяцах май–август доля согласий 5.2% у ранних записей и 32.9% у поздних.
- **Выбросы** не удалялись. У выбросов по возрасту доля согласий 44.8%, у выбросов по `previous` 23.1%: это ценные клиенты, а не ошибки.

## 4. Модели

| Модель | Настройка | Выбранные параметры | val PR-AUC |
|---|---|---|---:|
| Dummy | нет | постоянная вероятность | 0.117 |
| Logistic Regression | GridSearchCV, cv=5 | C = 1 | 0.428 |
| MLP из sklearn | сетка, среднее по 3 seed | (32, 16), alpha = 0.25 | 0.451 ± 0.007 |
| Своя сеть на numpy | сетка, среднее по 3 seed | (64, 32), ReLU, L2 = 0.001 | 0.457 ± 0.003 |
| PyTorch | те же параметры, что у своей сети | (64, 32), L2 = 0.001 | 0.457 ± 0.002 |

**Своя сеть** ([src/numpy_mlp.py](src/numpy_mlp.py)): только numpy, инициализация He, ReLU или tanh, бинарная кросс-энтропия, ручной backpropagation, Adam, L2, мини-батчи по 256, early stopping с возвратом лучших весов.

**Проверка корректности.**

- Сравнение backprop с численной производной: относительная ошибка меньше 1e-9.
- Ручной расчёт одного шага совпал с классом: loss снизился с 0.5928 до 0.5285.
- Независимая реализация на PyTorch дала тот же результат в пределах разброса.

**Что показал подбор.** Все пять лучших конфигураций своей сети используют L2 = 0.001, а 2 и 3 скрытых слоя дают близкий результат. ReLU немного лучше tanh: 0.457 против 0.448. Без L2 train loss падает до 0.25, а val после 20-й эпохи растёт, это переобучение (график 07).

## 6. Диагностика: проверка по времени

Те же модели обучены на первых 85% строк (согласий 6.8%) и проверены на последних 15% (согласий 39.3%).

| Модель | ROC-AUC случайное | ROC-AUC по времени | PR-AUC по времени |
|---|---:|---:|---:|
| Dummy | 0.500 | 0.500 | 0.393 |
| Logistic Regression | 0.771 | 0.640 | 0.516 |
| MLP из sklearn | 0.784 | 0.649 | 0.525 |
| Своя сеть на numpy | 0.789 | 0.630 | 0.515 |
| PyTorch | 0.783 | 0.641 | 0.523 |

Качество заметно падает, а порядок моделей меняется. PR-AUC выросла только потому, что положительных в этом периоде намного больше: прирост к Dummy 0.12–0.13 вместо 0.31–0.33.

## 7. Итог

1. **Какая модель лучше.** На случайном разбиении своя сеть (PR-AUC 0.447), разница с логрегрессией статистически подтверждена.
2. **Что выбрать на практике.** Логистическую регрессию как рабочую версию: обучение за доли секунды, понятные коэффициенты, на проверке по времени она на уровне сетей. Сеть имеет смысл, только если 3.7 процентных пункта захвата окупают сложность.
3. **Главное ограничение.** Данные нестационарны: модель надо регулярно переобучать и проверять по времени.

**Другие ограничения.**

- Гиперпараметры подбирались на val со случайным разбиением.
- `campaign`, `day`, `month` и `contact` описывают текущий контакт и должны быть известны заранее из плана кампании.
- В данных нет года, поэтому время оценено только по порядку строк.
- Причина низкой стабильности sklearn MLP (early stopping по accuracy) это гипотеза, она отдельно не проверялась.
- Необязательный TensorFlow не использовался: он не установлен для Python 3.14.
